对于一个较长的字符串（我们称之为主串或文本串）以及另一个较短的或者至少一样长的字符串（我们称之为子串或者模式串）， 我们想知道主串是否包含了字串，以及它的具体位置，应该怎么做呢。 
最简单的想法是我们可以从主串的开头逐字符匹配字串，如果失配了，主串往下一个字符， 再开始逐字符匹配。这种方法简单易懂，但是很明显不是最优的算法，举例像主串为ABCDEFZABCDEFG， 子串为ABCDEFG的情况下，我们匹配到Z时失配，很明显的，我们不需要从第一个A后面的BCDEFZ开始匹配， 因为他们很明显都不是A，自然不可能时子串的开头。有没有一个方法，让我们能跳过这些已经遍历过的字符， 直接开始对新的字符匹配呢？ 
这就是接下来要引入的kmp算法。在讲述这个算法之前，我需要说明，在一些课本中，比如我的课本， 会使用到next和nextval数组，我们不使用。同时我们也不使用1-based，而使用0-based， 即将字符串的第一个字符索引设为0。我也不推荐各位先学习另外一种做法，我觉得它极其难以理解， 被它折磨了很久。如果你完全没接触过kmp，那么可以忽略这段话，直接看接下来的内容。 
我们先观察什么时候可以跳过前述字符串，什么时候不能，在一些情况下，我们应该直接跳过前面的所有访问过的字符串， 如下面的例子： 
主串：ABCDEFZABCDEFG 
子串：ABCDEFG 
在标红的Z处失配，我们应该直接跳到下一个字符，即第二个A处继续尝试匹配。 
那么什么时候是特殊情况呢，我们看下面的例子： 
主串：ABCDEABCDEAG 
子串：ABCDEAG 
在标红的B处失配，我们应该从红B开始继续尝试匹配， 因为失配时最后的AB刚好是子串的第一二个字符。我们看下一个例子。 
主串：ABCDABCDABD 
子串：ABCDABD 
我们在红C处失配，但是我们发现， 这个地方刚好可以匹配上子串的第一个B，因此我们应该从红B开始继续匹配，也即从子串的第二个字符开始匹配。 
篇幅有限，我们不举更多例子，读者可自行举例。我们可以得到的结论是，失配时所匹配到的子串位置为j时， 我们应该回退到子串的border[j-1]处继续匹配， 其中border[n]表示子串的前n+1个字符的最长相等前后缀（前后缀均不等于自身）长度。 
这句话较难理解，举例来说，ABABACA的border数组计算方式如下： 
border[0] = 0 （A不存在不等于自身的前后缀） 
border[1] = 0 （AB只有前缀A与后缀B，而他们不等） 
border[2] = 1 （ABA有前缀A与后缀A相等，AB与BA不等，最长相等前后缀为A） 
border[3] = 2 （ABAB有前缀AB与后缀AB相等，其他略） 
border[4] = 3 （ABABA有ABA与ABA相等） 
border[5] = 0 （ABABAC没有前后缀相等） 
border[6] = 1 （ABABACA有A与A相等） 
则ABABACA的border数组为0, 0, 1, 2, 3, 0, 1 
我们匹配的时候会分配两个指针，一个指向主串，一个指向子串，需要明确的是一般不是声明出指针变量， 用i与j来指向s1[i]和s2[j]是常见做法。 
在匹配时，i与j同时向后移，尝试匹配下一个字符，失配时， j变为border[j – 1]，也即指向子串的指针回退。 
为什么应该回退到那个地方呢，因为前后缀相等意味着在失配时这里刚好还可以匹配开头的与后缀长度相等的一个地方。 其实这个很难表达清楚，读者可以自行举例验证。
